# Підготовлена система аудіотеки Callout

**Поточний стан:** усі згенеровані записи та їхні копії у Web-ресурсах і збірці видалено на запит власника. Маніфест містить 0 записів. Piper, моделі, каталог фраз, генератор та сервіс відтворення залишені. Системний голос/текстовий режим працюють як резерв. Не запускайте повторну генерацію без нового запиту власника. Наведені нижче числа 230 та результати декодування описують попередній запуск, а не наявну аудіотеку.

## Історія попередньої генерації (файли вже видалено)

- 230 англійських OGG Vorbis, усі створені наявною моделлю **en_US-ryan-medium** через установлене Piper-середовище.
- 20 поточних позицій Mirage, їхні перевірені англійські альтернативи та 10 типів фраз: назва, One, Two, Enemy, Last one, They're pushing, Enemy spotted at, Enemy near, Watch, Enemy at.
- Сценарії раундів також читаються автоматично. Якщо сценарій міститиме новий текст, який не покритий шаблонами, каталог додасть його як окрему стабільну фразу.
- Папка результатів: `/home/dima/callout-voices/generated/en/mirage/<position>/<variant>--<name-key>.ogg`.
- Приклад: `generated/en/mirage/window/one--primary.ogg`.
- Загалом приблизно 183,19 секунди, 2 315 993 байти OGG (близько 2,32 MB). Частота всіх поточних записів — 22050 Гц, один канал.
- Наявної української Piper-моделі не знайдено. 200 українських фраз є в автоматичному каталозі, але для них не створено хибних записів англійським голосом. Працює системний український голос або текстовий режим.

Назва продукту залишається **Callout**.

## Запуск

У корені проєкту:

```sh
npm run voices:generate
npm run voices:sync
npm run voices:test
npm run check
```

Або безпосередньо:

```sh
/home/dima/callout-voices/.venv/bin/python \
  /home/dima/callout-voices/scripts/generate_callouts.py
```

`/home/dima/callout-voices/scripts/generate_callouts.py` — посилання на версіонований `scripts/generate_callouts.py` цього проєкту, тож немає двох незалежних копій генератора. Компоненти не перевстановлювалися.

Для перевірки всіх наявних записів без генерації:

```sh
/home/dima/callout-voices/.venv/bin/python \
  /home/dima/callout-voices/scripts/generate_callouts.py --verify-only
```

Коли буде встановлено справжню українську Piper-модель та її `.onnx.json`, можна передати `--uk-model /absolute/path/model.onnx`. Скрипт перевірить `language.code` у конфігурації та відмовиться використовувати іншу мову. Автоматичний пошук також перевіряє моделі в `/home/dima/callout-voices`. Зараз це підготовлений шлях розширення, а не твердження про створений український пак.

## Єдине джерело фраз

`scripts/export-audio-catalog.ts` імпортує поточний `dictionary`, `scenarios` та `buildAudioCatalog()`. Окремого вручну продубльованого словника немає. У каталог потрапляють лише перевірені позиції доступних карт із посиланнями на джерела та підтверджені альтернативи. Inferno/Dust II не отримують фальшивих записів, доки їхні набори не готові.

`js/core/audio-catalog.ts` містить лише спільні мовні шаблони; їх використовує також LearningEngine. Стабільний ID має вигляд `en.mirage.window.one.primary`. Ідентифікатор альтернативи утворюється з її назви, без випадкових імен файлів. Українська має стандартний мовний код `uk`, а в інтерфейсі позначена UA.

## Генерація й обробка

Piper завантажується один раз на модель. Тимчасовий WAV створюється поза вебресурсами. FFprobe визначає його реальну частоту, після чого виконується:

```text
asetrate=<actual_sample_rate>*0.95,aresample=<actual_sample_rate>,atempo=1.26
```

Для поточної моделі це `asetrate=22050*0.95,aresample=22050,atempo=1.26`. Підсумкове співвідношення швидкості — `0.95 × 1.26 = 1.197`, тобто приблизно 120%. Інша частота автоматично підставляється замість 22050; це перевірено окремим реальним тестом на 48000 Гц.

Нормалізація — двопрохідний `loudnorm` з I=-18 LUFS, TP=-2 dBTP, LRA=7. Для надто коротких назв, де інтегрована гучність не визначається, застосовується пікова нормалізація до -3 dBFS. Вихід — mono OGG Vorbis, quality 5, з початковою частотою дискретизації. Ефектів рації, шуму, реверберації чи додаткового спотворення немає.

Кожен результат перевіряється FFprobe, повністю декодується FFmpeg, вимірюється пік. Для поточного пакета виміряні піки від -6,8 до -1,5 dBFS; файли з піком ≥0 dBFS відхиляються. 217 записів пройшли двопрохідну нормалізацію, 13 — нормалізацію короткого кліпу.

## Маніфест та інкрементальність

`/home/dima/callout-voices/manifest.json` містить текст, ID позиції/фрази, мову, шлях, модель, тривалість, частоту, канали, кодек, піковий рівень, SHA-256 файла та fingerprint генерації. Також записуються параметри обробки, хеші моделі/конфігурації та версії інструментів.

Fingerprint змінюється, якщо змінено текст, модель, конфігурацію, налаштування обробки або версію інструментів. Готовий файл пропускається лише за збігу fingerprint, SHA-256 та успішної перевірки/декодування. Пошкоджені або застарілі записи перегенеровуються. Файли та маніфест публікуються атомічною заміною; невикористані старі файли автоматично не видаляються.

Фактично виконано повну генерацію (230 нових, 0 помилок) і повторний запуск (0 нових, 230 пропущено, 0 помилок).

## Синхронізація та Web

`npm run voices:sync` перевіряє покриття поточного англійського каталогу й контрольні суми та копіює лише маніфест і вказані в ньому OGG у `assets/audio/`. Команда запускається автоматично перед `npm start` і `npm run build`. Якщо папки генератора на іншому комп’ютері/CI немає, перевіряється включений у репозиторій пак. Застарілий пак спричиняє зрозумілу помилку з вимогою повторити генерацію.

Production містить лише активні записи у `dist/assets/audio/`; `.venv`, `.onnx`, Python і тимчасові WAV не копіюються. Усі записи включені до production service worker для офлайн-роботи після успішного встановлення кешу.

## Відтворення

`AudioCalloutService` зіставляє мову, стабільний ID позиції та точний текст/ID фрази. Є обмежений кеш попереднього завантаження, послідовне відтворення кількох колаутів, зупинка попереднього повідомлення та захист від пізнього відтворення після виходу зі вправи. `exerciseAudio()` визначає звук для всіх режимів; у неаудіорежимах доступна кнопка прослуховування.

Listening, Voice Simulator і звичайні раунди відтворюють повідомлення автоматично. Multi-Callout послідовно використовує окремі записи. Зворотна комунікація не озвучує правильну відповідь автоматично; явне прослуховування є підказкою й не дає незалежних навчальних балів.

Налаштування:

- **Записи Ryan · системний резерв** — стандартний режим.
- **Лише системний голос** — явний вибір користувача.
- **Озвучування вимкнено** — без відтворення.
- Гучність, окрема швидкість системного TTS, окрема явна швидкість записів і кнопка перевірки.

Швидкість записів за замовчуванням **1×**: обробка Ryan не застосовується повторно. Автоматичне прискорення симулятора стосується лише системного TTS. Якщо запис відсутній або Vorbis не підтримується браузером, використовується локальний Web Speech відповідної мови. За відсутності обох джерел — явний текстовий режим без аудіобалів. Блокування автовідтворення показується окремо, щоб користувач міг натиснути динамік.

## Межі перевірки

Виконано генерацію, FFprobe і повне декодування всіх 230 файлів, повторну перевірку кешування, тести AudioCalloutService з керованим медіаадаптером, покриття фраз усіх режимів, тести Python/FFmpeg та production-збірку. Перевірено наявність кожного файла у збірці, контрольні суми та включення до офлайн-кешу. Фактичного прослуховування й браузерного тесту динаміків не виконано: браузерний інструмент повертає `The browser access host is unavailable`. Технічна коректність файлів не є суб’єктивною оцінкою тембру чи вимови.
